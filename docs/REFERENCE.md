# Workflow reference

All workflows are generated by `tools/build_workflows.py` from `config.json` (edit config, re-run, re-import; do not hand-edit the JSON). Every external call (GoHighLevel, Twilio, Google, Vapi) retries and continues on error so one failing system never blocks the others. Tool workflows reply to Vapi first and update the CRM afterwards, so the caller never waits on GoHighLevel.

| # | Workflow | Trigger | What it does |
|---|----------|---------|--------------|
| 01 | Lead Intake - Outbound Call | `POST /webhook/lead-intake-<token>` | Normalises one lead or a batch, formats the phone to E.164, checks consent, calling window, duplicates (dedupe window) and the DNC sheet, then asks Vapi to place the call. Leads outside the window are queued in Callbacks for the next window start. Creates/updates the GoHighLevel contact, opportunity (stage New Lead -> Contacted), tags and a note. Logs skipped leads. |
| 02a | Vapi Tools - Calendar and Listings | `POST /webhook/vapi-tool-check-availability`, `-book-viewing`, `-search-listings` | Free/busy lookup and slot generation (hours, buffers, minimum notice); re-checks the slot, creates the calendar event, texts the confirmation, moves the opportunity to Viewing Booked; filters the Listings tab. |
| 02b | Vapi Tools - Leads and Compliance | `-save-qualification`, `-schedule-callback`, `-opt-out` | Scores the lead (hot/warm/cold), updates contact fields, tags and stage, alerts agents by SMS (and Slack) on hot leads and says whether a live transfer is available; queues callbacks (AI or human); handles opt-out end to end. |
| 03 | Vapi End-of-Call Report | `POST /webhook/vapi-events` | Classifies the outcome (conversation, voicemail, no answer, transferred, error, silent), writes summary, transcript link and fields to GoHighLevel, logs the call, schedules retries up to `max_attempts`, catches missed opt-outs from the transcript, ignores duplicate events, alerts if a tool failed during the call. |
| 04 | Twilio Inbound SMS - Opt-Out | `POST /webhook/twilio-sms-<token>` | STOP-style replies -> DNC, GHL DND, cancel callbacks. Other replies are logged on the contact and can alert an agent. Returns empty TwiML. |
| 05 | Callback Scheduler | every `scheduler_interval_minutes` | Picks due callbacks inside the calling window (max `scheduler_max_per_run`), re-checks DNC, places the Vapi call, marks the row done. Human callbacks alert an agent instead. |
| 06 | Error Handler | Error Trigger | Any uncaught failure in 01-05 sends an SMS (and Slack if configured) with the workflow, node and message. |

Webhook security: Vapi tool and event webhooks require header `X-Vapi-Secret` (n8n Header Auth credential "Vapi Webhook Secret"). The intake and Twilio webhooks are protected by an unguessable path token; keep those URLs private. Twilio signature validation is not implemented.

## Lead scoring (config.json -> scoring)
Score = timeline + financing + specificity + engagement, capped at 100. **Hot >= 70, warm >= 40, else cold.** `not_interested` forces cold.
- Timeline: immediately 35, within_1_month 30, 1_3_months 20, 3_6_months 8, 6_plus_months 3, just_browsing 0.
- Financing: cash 25, pre_approved 25, ready_to_apply 22, mortgage_in_progress 14, not_started 5.
- Specificity: budget 8, area 7, bedrooms 5.
- Engagement: viewing interest yes 15 / maybe 6, viewing booked 15, asked for an agent 5.
Adjust weights and thresholds in config and rebuild.

## Data written to GoHighLevel
Tags: `ai-lead`, `source-<x>`, `ai-call-placed`, `ai-qualified`, `tier-hot|warm|cold`, `intent-buy|rent`, `viewing-booked`, `callback-scheduled`, `agent-callback`, `do-not-contact`. Custom fields: the 20 `AI ...` fields (intent, budget, area, bedrooms, timeline, financing, score, tier, source, call summary, notes, last call id/time, attempts, next callback, opt-out, viewing datetime/event/call). Pipeline stages: see `ghl.stage_names`. Notes: booking, callback, opt-out and call summaries.

## Vapi tools (JSON in `vapi/`)
| Tool | Arguments (required in bold) |
|------|------------------------------|
| check_availability | preferredDate, timeOfDay |
| book_viewing | **startISO**, firstName, lastName, email, listing, notes |
| search_listings | query, intent, area, minBedrooms, maxPrice, minPrice, propertyType, listingRef |
| save_qualification | **intent**, budgetMin, budgetMax, preferredArea, bedrooms, timeline, financing, viewingInterest, wantsAgent, outcome, firstName, lastName, email, notes |
| schedule_callback | **callbackLocalTime** (local, YYYY-MM-DDTHH:MM:SS), reason, notes, firstName |
| opt_out | reason |
| transfer_call | built-in transfer to `agents.transfer_numbers` |
| end_call | built-in |
Tool replies follow Vapi's contract: HTTP 200 with `{"results":[{"toolCallId","result":"<json string>"}]}`; on failure `ok:false` with a message the assistant is told to relay, never to guess around.

## Changing things
- Script/tone: edit `prompts/*.md`, run `configure_vapi.py` (updates in place).
- Hours, retries, scoring, viewing rules: edit `config.json`, run `build_workflows.py`, re-import.
- Different voice or model: `vapi.voice`, `vapi.llm_model` in config, then `configure_vapi.py`.
